# Tech Stack — Expo · React Native · TypeScript

The technologies this mobile client uses. Use the current stable release of each; the lockfile pins versions, not this file. Anything not listed is added only after approval: the build plan names what the feature needs and recommends the most secure, efficient and standard option for this stack.

The app is the client only. The backend (NestJS or FastAPI, built with the Backend Blueprint) is the single authority for data, business rules and authentication. The app holds no business logic, is not the API, and runs no auth of its own. iOS and Android are one client with one codebase; the platforms differ in conventions, never in features.

## Application

| Need | Choice |
| --- | --- |
| Language · runtime | TypeScript in strict mode · Hermes, on the New Architecture (the only architecture since SDK 55) |
| Framework | Expo SDK, current stable. Development builds (`expo-dev-client`), never Expo Go. Continuous Native Generation: `ios/` and `android/` are generated by `expo prebuild` and not committed; native configuration lives in `app.config.ts` and config plugins |
| Routing | Expo Router, with typed routes on |
| Styling | Tailwind CSS v4 through Uniwind |
| UI components | React Native Reusables — copied into the repo and owned there · `lucide-react-native` icons · `sonner-native` toasts |
| Lists | `@shopify/flash-list` for every list of unknown length |
| Animation | `react-native-reanimated` and `react-native-gesture-handler`, both bundled with Expo: micro-interactions, springs, entry and exit, layout changes, drag and drop, custom transitions. Screen transitions come from the native stack and are configured, not animated by hand |
| Animation, on demand | `lottie-react-native` for ready-made vector animations · React Three Fiber with `expo-gl` for 3D · `@shopify/react-native-skia` for custom-drawn graphics, with Victory Native for charts. Installed only when a feature needs them, never by default |
| Server data | TanStack Query: caching, refetching, mutations, pagination, optimistic updates. Online state from `@react-native-community/netinfo`, focus from `AppState` |
| HTTP | `expo/fetch` through the project's `apiFetch` wrapper · `expo-file-system` upload tasks for uploads that need a progress bar |
| API types | `openapi-typescript`, generated from the backend's OpenAPI spec into `src/types/api.ts` |
| Global UI state | Zustand — only for state the server does not own (drafts, wizard steps, UI flags) |
| Persisted state | Zustand's `persist` middleware on MMKV (`react-native-mmkv`): preferences, onboarding status, drafts. Never tokens, never server data |
| Secrets on the device | `expo-secure-store`: the refresh token, and nothing else |
| Session | Access token in memory, refresh token in SecureStore; `apiFetch` refreshes. The backend issues and rotates both |
| Forms · validation | React Hook Form · Zod, through `@hookform/resolvers` |
| Environment variables | `@t3-oss/env-core` with Zod and `runtimeEnvStrict`, each `EXPO_PUBLIC_` variable referenced statically so Expo inlines it: validated at startup, set per environment in EAS |
| Mocking | MSW (`msw/native`) for tests · this app's in-process mock handlers for the build-before-integration phase (`coding-standards` → Mock mode) |
| Dates | `date-fns` |
| Images | `expo-image`: caching, placeholders, transitions |
| Fonts | `expo-font`: Google Fonts through `@expo-google-fonts/*`, other open-source fonts as files in `assets/fonts/` |
| Keyboard | `react-native-keyboard-controller` |
| Safe areas | `react-native-safe-area-context` |
| Haptics | `expo-haptics`, as `DESIGN.md` → Motion specifies |
| Push notifications | `expo-notifications`: permission, the Expo push token, foreground presentation, taps. The backend sends them |
| Deep links | `expo-linking` with Expo Router: a custom scheme, plus universal links (iOS) and app links (Android) |
| Sign-in providers | `expo-apple-authentication` · `expo-auth-session` with `expo-web-browser` for Google and other OAuth providers, PKCE in the system browser · `expo-local-authentication` for biometric unlock, where the product uses it |
| Payments | `react-native-purchases` (RevenueCat) for digital goods and subscriptions, as the stores require; without RevenueCat, `expo-iap` with the backend verifying purchases directly · `@stripe/stripe-react-native` for physical goods and services |
| Real-time | SSE through `expo/fetch` streaming · WebSocket through React Native's `WebSocket`, or the Socket.IO client where the backend uses Socket.IO — as the api-docs specify |
| Over-the-air updates | `expo-updates` through EAS Update, `runtimeVersion` on the `fingerprint` policy |
| Splash and icons | `expo-splash-screen` · app icon, adaptive icon and splash per environment from `app.config.ts` |
| Error tracking | `@sentry/react-native`, with its Expo config plugin |
| Product analytics *(optional)* | `posthog-react-native`. The `analytics` rule applies when it is installed |
| Lint · format · types | ESLint (`eslint-config-expo`, `eslint-plugin-testing-library`) · Prettier with `prettier-plugin-tailwindcss` · `tsc` |
| Package manager | pnpm, with a committed lockfile and the `.npmrc` settings Expo's pnpm guide requires |
| Unit and integration tests | Jest with the `jest-expo` preset · React Native Testing Library · MSW |
| E2E and smoke tests | Maestro, flows in `.maestro/` |
| Bundle analysis | Expo Atlas, run by hand |

**Added when a feature needs them**, through the build plan: `@gorhom/bottom-sheet`, `expo-camera`, `expo-image-picker`, `expo-location`, `expo-maps`, `expo-contacts`, `expo-calendar`, `expo-document-picker`, a rich-text editor, `expo-localization` with an i18n library for a second language.

## Services

| Need | Local | Development build | Staging | Production |
| --- | --- | --- | --- | --- |
| The app | `expo start` into a development build on a simulator, emulator or device | EAS Build, `development` profile: a dev client, internal distribution | EAS Build, `staging` profile, internal distribution: TestFlight internal testers and the Play internal track | EAS Build, `production` profile: App Store and Google Play |
| App identity | the development build's | `{bundle id}.dev`, "{Name} Dev" | `{bundle id}.staging`, "{Name} Staging" | `{bundle id}`, "{Name}" |
| OTA channel | — | `development` | `staging` | `production`, after `production-smoke` |
| Backend API | Mock mode, passing un-mocked units through to staging | Mock mode, passing through to staging | Staging backend; mock mode with passthrough while any unit is un-integrated | Production backend, direct |
| Error tracking | — | Sentry, `development` environment | Sentry, `staging` environment | Sentry, `production` environment |
| Analytics *(optional)* | — | — | PostHog, staging project | PostHog, production project |
| Push | — | Expo's push service, with this project's EAS push credentials; the backend sends | Same | Same |
| CI/CD | — | GitHub Actions, with EAS Build, Submit, Update and Workflows | Same | Same |

- **Three apps side by side.** Development, staging and production builds have different bundle ids, names and icons, from one `app.config.ts` keyed by `APP_ENV`, so all three install on one device and a tester never mistakes one for another.
- **Environment variables are baked in at build.** `EXPO_PUBLIC_API_URL` and the rest differ per environment, so each environment is its own build, and an over-the-air update carries the values of the environment it was published to.
- **An update only reaches a compatible build.** The runtime version is the native fingerprint, so a JS-only update is applied by every build with the same native code and ignored by every other.
- **Custom domains matter less than on the web.** The app authenticates with a bearer token, not cookies, so it talks to the API at any URL. Universal and app links need the product's web domain to serve the `.well-known` files `security` describes.
- **Sentry** receives source maps from EAS Build and EAS Update, scrubs what `security` says, and alerts on new issues per environment.
- **Media** is uploaded straight to the backend's bucket with presigned URLs the backend issues, and served from its CDN through `expo-image`; the app never holds storage credentials.
- **Expo's own agent skills** (`github.com/expo/skills`) may be installed beside these for SDK upgrades; they do not replace these rules.
